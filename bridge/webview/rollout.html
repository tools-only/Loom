Loom rollout architecture / 2026-06-11

把用户纠正、自动检测与学习更新收敛到同一条反馈闭环

这页不是单纯的数据字段清单，而是 Loom 如何把显式反馈、隐式纠正、共享存储、检测器和 learner 串成一张可落地的系统图。它既要能支撑工程实现，也要能在汇报里快速讲清楚这套机制为什么成立。

Shared Files 所有路径最终写到统一 store，消费方按 source 加权，不按入口分叉。
Dual Paths UI 路径负责高精度，自动路径负责高覆盖，两条路在 detector 之前就对齐数据结构。
Closed Loop 反馈被写回 learned notes、ranking、prompt policy，避免同类错误重复出现。

Collection Paths

这两条路径不是竞争关系，而是刻意互补。A 路提供少量高精度种子，B 路扩大扫描覆盖，再通过 source 和 confidence 做权重分层。

Path A

Explicit user feedback

high precision
  • 触发方式 thumbs up/down、纠正按钮、结构化评论输入。
  • 优势 用户意图最明确，误判空间最小，适合做 seed labels 与 golden cases。
  • 限制 大部分用户不会主动点击，天然低覆盖，不能独立承担学习闭环。
  • 工程要求 只需要稳定的反馈 API 和明确事件 schema，不要把学习逻辑塞进 UI 层。
Precision >95%
Coverage Low

Path B

Implicit correction scan

high coverage
  • 触发方式 定时扫描 turn pairs，判断 human next input 是否在纠正上一轮 agent 输出。
  • 优势 能覆盖用户没有点击反馈控件的绝大多数场景，更适合大规模发现错误模式。
  • 限制 存在假阳性，需要 confidence、去重和后验评估，不适合直接替代人工确认。
  • 工程要求 intent stream 必须同时记录 agent output 与 human input，detector 只负责判别与抽取。
Precision ~70%
Coverage High

Detection and Learning Loop

真正的系统价值不在“收集到反馈”，而在“反馈如何稳定进入下次行为”。这一段把 detector、flywheel 和 learner 的边界讲清楚。

1

Detect

CorrectionDetector 从相邻 turn 对中判断是否存在“用户纠正上一步输出”的信号，并提取 correction、agent claim、confidence。

2

Normalize

无论来自 UI 还是 detector，事件都被整理为统一 feedback schema，差异只落在 source、confidence 和可追踪上下文。

3

Aggregate

flywheel records 把单个 feedback event 聚合为 episode 级学习材料，方便后续做总结、比较和人工审阅。

4

Apply

learner 把高价值结论写回 learned notes、资源排序或 prompt policy，让 hand 在下一轮执行前真正读到这些变化。

Boundary Rules

  • Detector does not update policy directly 它只产生带置信度的结构化信号，避免单次误判直接污染 hand 行为。
  • Shared stores stay append-only 所有原始事件都应保留，后续权重、过滤与总结放在消费者层完成。
  • Learning outputs must be operator-readable 只写隐含状态不够，至少 learned notes 或 episode record 必须可复盘。
  • Confidence affects weighting, not persistence 低置信度事件也值得保留，但不应与显式用户纠正等权处理。

Implementation Checklist

最后一屏给工程同学一个能直接开干的清单。每条都对应清晰边界，避免“做个 detector”这种空泛任务。

校验 intent stream 内容边界 确认每个 turn 至少能区分 human input 与 agent output，并能建立相邻 pair。
定义 correction event schema 补齐 source、confidence、agent_claim、correction_text、cursor 等字段，避免 detector 与 learner 对不齐。
实现 detector scan cursor 记录已处理 pair 的位置，防止重复扫描同一相邻 turn 并产生重复 feedback。
建立 A/B signal overlap review 用 UI path 的高精度样本校验 detector，按周看 precision 与 false positive 类型。
把 learner 输出落到可读介质 至少写回 learned notes 或 episode summary，确保 operator 和 hand 都能消费结果。
保持 UI 层简单 前端只发事件，不承担 detector、学习或聚合逻辑，减少后续 schema 变更成本。
