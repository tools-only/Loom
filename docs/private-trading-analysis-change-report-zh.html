1. trading/trading-canvas-renderer.cjs 338 行

交易分析画布的 HTML 模板生成器，使用 Bloom Design System CSS 类。生成包含 7 个数据锚点的初始模板，每个锚点带有 domain 元数据属性：

提供业务对象 HTML 构建器：buildClaimHTML、buildThreadHTML（bull/bear/perspective）、buildFindingHTML、buildReactionHTML、buildPositionSummaryHTML。Domain 元数据属性：data-domain="trading.private"、data-trading-session-id、data-claim-id、data-finding-id。

2. trading/trading-events.cjs 276 行

交易 domain 事件层。采用依赖注入（DI）模式，通过 initialize(deps) 接收 server.cjs 的核心函数引用。所有 trading 事件通过同一个 recordEvent() 写入 logs/sessions/*/events.jsonl，与现有 Anchor 事件共存，通过 kind: "trading.*" 前缀区分。

每个事件 payload 均携带 trading_session_id、actor、visibility: "private"。提供 replayTradingSession(events, tradingSessionId) 从事件流重建业务状态。

4. trading/policy-gate.cjs 113 行

Finding 提交前的策略校验模块。检查项：

  1. 必须绑定 claim_id
  2. 必须声明 stance（supports / rebuts / complicates）
  3. 必须包含 evidence 或 observed_at
  4. visibility 必须为 "private"
  5. 不得包含直接买卖建议（正则匹配 buy/sell 模式）

返回 { ok: boolean, violations: string[] }。违规时产生 trading.policy_rejected 事件而非写入 finding。

三、架构决策

依赖注入模式

Trading 模块不直接 require('mcp/server.cjs')（会导致循环依赖），而是通过 initialize(deps) 接收 server 函数引用。currentSession 使用 getter 传递，确保始终读取 server 模块内的最新值而非 require 时的快照。

事件共存策略

Trading domain 事件通过同一个 recordEvent() 写入同一个 events.jsonl，与现有 Anchor 事件共存。区分方式：事件 kind 前缀为 "trading.*" vs 现有的 "user.*" / "agent.*" / "system.*"。replayTradingSession() 扫描全部事件并按 trading_session_id 过滤。

零回归保障

防护点机制
Envelope 校验domain 字段类型为 ['object', 'null']，缺失或为 null 时不做任何额外校验
recordEvent()函数体未修改，仅调用方传入不同的 kind 前缀
deliverOp()函数体未修改，trading ops 通过现有 processor pool 路由
Workspace API仅在 req.body.domain === 'trading.private' 时注入 trading 模板和 session
Browser WS handlerTrading 逻辑在独立 if 块内，else 分支行为不变
CSS / HTML仅使用现有 Bloom CSS 类（anc-section、anc-pill 等），无新增 CSS 文件和图标库
路由全新 /trading/* 路径前缀，无现有路由被重命名或移除

四、数据流

Browser: 用户点击 data-anc="trade.intent" └→ anchor-client.js buildEnvelope() 检测 data-domain，添加 domain 字段 └→ WebSocket {type:"envelope", envelope:{ ..., domain:{namespace:"trading.private", action:"DECLARE_REASONING", trading_session_id:"trd_...", ...} }} └→ server.cjs wssBrowser handler ├→ validateEnvelope() — 通过（domain 为可选字段） ├→ recordEvent('user.intent', envelope) → events.jsonl ├→ tradingEvents.recordTradingEvent('trading.reasoning_declared', payload) → 同一 events.jsonl └→ deliverOp() → processor pool → CC agent → anchor_patch → browser
