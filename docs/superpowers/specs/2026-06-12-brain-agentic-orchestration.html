Loom Brain · Agentic Orchestration

把 Brain 从固定 fanout 升级为 state-first 的任务编排中枢

当前方案的核心是：Brain 不再只是把问题扔给几个固定 hand agents，而是先建立可查询、可持久、可复盘的 workflow state， 再基于 goal、rubric、任务图和验收标准动态创建/编排 hand agents，最后验收、补跑、汇总，并为固定任务提供无 UI 的高效率 data rollout。

状态先验 动态 hand 流程 固定任务持久 hand Headless HTTP JSON API Goal + Flywheel 复盘

一、目标状态

Brain 的职责升级为完整 agent 流程控制器：任务理解、目标建模、rubric 设计、hand agent 创建、并行/串行编排、成果验收、缺口补跑、最终 synthesis 和数据沉淀。

  • 正常任务：继续和人类通过现有 UI 交互，保留 `/analyze`、presentation、card drill-down 体验。
  • 固定任务：例如 `loom-fin` 市场研判、个人仓位管理、科研调研等，允许沉淀为持久 hand/task 定义。
  • 高频自动化：固定任务通过 headless HTTP JSON API 输出结构化 data product，不依赖 UI patch。

当前代码基础

  • `LoomCoreAgent.analyze()` 已有 plan → dispatch → review → synthesize 雏形。
  • `BrainState` 已能按 domain 查询 rules、frameworks、notes。
  • `GoalContextStore`、`FlywheelWriter` 已存在。
  • 主要缺口是 workflow state 还不是一等对象，hand 选择仍偏固定。

二、State-First Pipeline

1. State Select从 BrainState、IntentWiki、GoalContext 选择本次任务的先验上下文。
2. Goal Plan明确 goal、success criteria、rubric 维度、排除项和验收策略。
3. Hand Plan按子任务生成 runtime 或 persistent hand specs，而不是写死四个 hand。
4. Dispatch根据 spec 绑定现有 adapter、SDK hand 或外部 agent 执行。
5. Acceptance Review按 rubric coverage、evidence、source freshness、confidence gaps 验收。
6. Repair Loop缺口明确时生成 follow-up hand task，补齐后再 synthesis。
7. Synthesis输出 stance、confidence、drivers、reversal、watch conditions 和 data product。
8. Persist写入 GoalContext、Flywheel、intent stream agent_output 和 headless run result。

三、Hand Agent 策略

Runtime

日常通用任务

不新建长期 hand。Brain 为每个 rubric/sub-question 生成临时 hand spec，绑定现有 adapter 或通用 agent 执行。

  • 适合一次性分析、白板协作、临时研究。
  • 结果进入 episode/flywheel，不污染长期 hand registry。
  • hand spec 随 workflow state 返回，便于复盘。
Persistent

固定任务域

对用户反复搜寻/执行的固定任务，Brain 可以沉淀 hand/task 定义，用于后续自动化。

  • 适合 `loom-fin`、仓位管理、科研调研。
  • 写入受控的 generated hand spec store 或 domain task registry。
  • 需要可读配置、版本、capabilities、artifact contract。

五、Headless Data Rollout

固定任务不必经过 UI。新增 Brain run API，直接返回 JSON，适合脚本、定时任务、外部 dashboard、移动端摘要和后续自动复盘。

POST /brain/runs
{ "question", "domain_hint", "goal_type", "rollout": "headless" }

GET /brain/runs/{episode_id}
返回 synthesis、rubric_coverage、hand_artifacts、workflow_state、data_product、quality_gaps。

GET /brain/runs?domain=finance&status=latest
用于固定任务的近期结果查询。

`/analyze` 继续负责 UI patch 和 presentation；`/brain/runs` 只做数据执行与结构化返回。两者共享同一个 `LoomCoreAgent` pipeline，避免双轨逻辑。

六、实施顺序

  1. 在 `LoomCoreAgent` 中引入 workflow state，并让每个 phase 显式读写 state。
  2. 在 `BrainHarness` 增加 `plan_goal`、`plan_hands`、`review_acceptance`、`build_data_product`。
  3. 把 resolver 降级为 domain/task-pack resolver，不再直接决定固定 hand fanout。
  4. 增加 generated hand spec store，用于固定任务持久化。
  5. 新增 `/brain/runs` headless API，并把 run result 存入 episode/flywheel。
  6. 补齐 agent_output intent-stream 事件，为后续 CorrectionDetector 做 turn-pair 数据基础。

七、验收标准

  • 固定域任务返回 persistent hand specs，并能复用到后续同类任务。
  • 通用任务只生成 runtime hand specs，不写长期 hand registry。
  • review 按 rubric coverage 验收，缺口明确时会触发 follow-up task。
  • headless API 返回可消费的 `data_product`，不依赖 UI HTML。
  • 现有 `/analyze`、presentation、hand artifact UI 不回退。
  • GoalContext/Flywheel 能追踪 episode、phase、hand specs、coverage 和质量缺口。

八、关键边界

持久 hand 创建必须受控：只允许固定任务域或明确用户意图触发，不能让任意 prompt 直接写入长期 hand 目录。Runtime hand 是默认路径，persistent hand 是经过 domain/task-pack 约束后的沉淀路径。
