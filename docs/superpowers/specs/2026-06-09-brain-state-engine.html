BrainStateEngine

Brain 侧独立状态管理模块。将当前碎片化的 IntentWiki / BrainState / RewardHarness 统一为一个有主权的、可演化的执行层：维护用户意图画像 → 派生策略 → 指导 Hand 编排 → 累积目标上下文 → 沉淀数据飞轮。

!设计动机

当前 Brain 是无状态的 Prompt Assembler

每次调用 Brain 都是全量重新拼接：BrainState（静态规则）+ IntentWiki（用户显式定义）+ IntentStream tail(5)（事件日志片段）+ RewardHarness（session-local）。这些组件之间没有统一的状态主权——没有"Brain 现在知道什么"，只有"Brain 每次能看到什么"。

核心缺失：用户意图不是由 Brain 维护的，而是用户在 IntentWiki 里手动定义的；策略不是从意图派生的，而是从规则文件里匹配的；Hand 的任务参数不是由当前策略驱动的，而是 LLM 一次性决定的；跨多个 synthesis call 的目标上下文没有积累——每次都从 last-synthesis.md（单条覆盖）重新开始。

结果：Brain 是一个聪明的单次回答机器，而不是一个有记忆、有策略、持续服务目标的协作伙伴。

BrainStateEngine — 五层结构

BrainStateEngine — 组件层次
Layer 1 IntentProfile 动态用户意图画像：当前信念状态、意图优先级、分析风格、意图速率
↓ 派生
Layer 2 StrategyState 从 IntentProfile 派生的高层策略：研究优先级、信息关注策略、框架选择、可验证评估维度
↓ 驱动
Layer 3 OrchestrationLayer Hand 编排：基于策略生成每个 Hand 的具体任务参数，执行冲突仲裁，对 Hand 结果按策略定义的维度评分
↓ 积累
Layer 4 GoalContext 目标上下文：跨 session 持续积累，纳入 Hand 关键结果、synthesis 快照、冲突记录，动态摘要
↓ 沉淀
Layer 5 DataFlywheel 结构化原生数据：Brain 自评 + Hand 评估 + Hand 自报告 + 人类反馈，按 episode_id 关联，反哺更新 Layer 1–2
现有组件归宿
IntentWiki 用户显式定义的耐久意图节点 → 继续存在，作为 IntentProfile 的种子输入
BrainState (rules/frameworks) 策略规则和分析框架 → StrategyState 的可用工具库
RewardedIntentHarness Policy planning + reward ledger → 重构为 DataFlywheel 的一部分
1Layer 1

IntentProfile — 动态用户意图画像

与 IntentWiki（用户显式定义、静态）不同，IntentProfile 是 Brain 从行为中推断和维护的动态模型。两者共存：IntentWiki 是人工种子，IntentProfile 是演化结果。

🧠

IntentProfile

brain/state/intent_profile.json
  • active_intents 有优先级和置信度的意图列表，自动从行为推断（比 IntentWiki 更动态）。每个意图有 zone、confidence、last_seen、evidence_count。扩展 IntentWiki
  • belief_state 用户当前对各 topic 的信念 {"NVDA": {stance: "bullish", confidence: 0.72, updated_at: "..."}}。从用户接受的 stance 和 strategy_edit 推断，捕获"用户现在认为什么"。新增
  • analytical_style 分析风格：density（详细/简洁）、framework_pref（倾向哪类分析框架）、risk_appetite、time_horizon。从 anchor ops 和 strategy edits 中学习。新增
  • intent_velocity 意图变化速率 [0-1]。高 velocity = 用户视野在剧烈调整（应降低 GoalContext 的惰性，更频繁更新策略）。低 velocity = 稳定期（GoalContext 可以积累更长时间）。新增
  • domain_focus 当前关注的 domain 层级：{primary: "market_research", secondary: ["macro", "sector_rotation"], ticker_watch: ["NVDA", "MSFT"]}。新增 
@dataclass
class IntentProfile:
    profile_id: str
    updated_at: str
    active_intents: list[IntentNode]          # 带置信度、来自 wiki + 推断
    belief_state:   dict[str, BeliefRecord]     # {topic: stance+confidence}
    analytical_style: StyleRecord                   # density, framework_pref...
    intent_velocity: float                       # 意图漂移速率
    domain_focus: DomainFocus                       # primary + secondary + tickers
与 IntentWiki 的边界：IntentWiki 里的节点是用户"声明"的意图（显式输入）；IntentProfile 里的内容是 Brain "推断"的意图（从行为中学到的）。两者都存在，IntentWiki 作为置信度较高的种子，IntentProfile 随使用持续演化。当两者冲突时，优先 IntentWiki（用户显式意图优于推断）。
2Layer 2

StrategyState — 从意图派生的可执行策略

策略不是人工定义的规则集合，而是由 Brain 从 IntentProfile 推导出来的执行计划：该研究什么、用什么深度、关注哪些信源、用哪些框架、以什么维度验证结果。

🗺️

StrategyState

brain/state/strategy_state.json
  • research_priorities 当前最重要的研究方向，按优先级排序。例：["NVDA Q3 earnings quality", "AI capex sustainability", "FedFunds path"]。由 IntentProfile.domain_focus + belief_state 推导。新增
  • information_strategy 信息关注策略：{source_weights: {sec_hand: 0.9, macro_hand: 0.7, sentiment_hand: 0.3}, recency_requirement: "daily", signal_focus: ["earnings_revision", "vol_regime"]}。新增
  • position_logic （仓位管理模式）维护各头寸的存续逻辑、触发条件和退出准则。{NVDA: {thesis: "...", hold_condition: "...", exit_trigger: "..."}}。新增
  • framework_selection 当前策略适用的分析框架 ID 列表，从 BrainState.frameworks 中按 IntentProfile 权重选取（已有 query_frameworks，扩展为策略驱动的主动选取）。扩展现有
  • evaluation_dims 可验证的评估维度：策略为每类 Hand 定义具体验证标准。例：[{hand: "earnings_hand", dim: "provides_consensus_eps", verify: "key_claims contains EPS figure", weight: 0.8}]。这使 Hand 评估从通用关键词匹配升级为策略特定的结构验证。新增 
@dataclass
class EvalDimension:
    dim_id:   str
    hand_id:  str
    label:    str                     # "provides current EPS consensus"
    verify:   str                     # "key_claims contains EPS figure"
    weight:   float                   # 在 synthesis quality 中的权重

@dataclass
class StrategyState:
    strategy_id:        str
    goal_id:            str
    derived_from:       str             # IntentProfile.profile_id
    updated_at:         str
    research_priorities: list[str]
    information_strategy: InfoStrategy
    position_logic:     dict[str, PositionLogic]
    framework_selection: list[str]
    evaluation_dims:    list[EvalDimension]
EvalDimension 是关键创新：当前的 evaluator（词袋匹配）是通用的、与策略无关的。StrategyState 让 Brain 在派生策略时同时定义"这次 Hand 的结果应该满足什么具体条件才算有用"。例：研究 NVDA 时，earnings_hand 必须提供 Q3 consensus EPS 数字——这是可验证的 boolean，远比"output_text 包含 'earnings' 关键词"精确。
3Layer 3

OrchestrationLayer — 策略驱动的 Hand 编排

策略不只是选择"调用哪些 Hands"，而是为每个 Hand 生成具体的任务配置参数，并在 Hand 执行后按 StrategyState.evaluation_dims 对结果进行结构化评分。

⚙️

OrchestrationLayer

brain/orchestration/

与当前 workflow_decision（LLM 一次性决定哪些 Hand，无参数）相比，OrchestrationLayer 的核心升级：

  • HandConfig 每个 Hand 的策略派生配置：{hand_id, focus: "rate sensitivity signals", depth: "deep", time_window: "30d", look_for: ["Fed communication", "yield curve"], exclude: ["noise sources"]}。Hand 按 config 调整 query 策略。新增
  • OrchestrationPlan MDP 编排计划（而非单步 bandit 选择）：{phase_1: [macro_hand, fundamental_hand], phase_2: {condition: "phase_1.confidence < 0.6", run: [sector_hand]}, phase_3: {condition: "contradiction_detected", run: [verification_hand]}}。新增
  • HandEvaluation 按 StrategyState.evaluation_dims 对每个 Hand 的结果评分：{hand_id, dim_scores: {dim_id: score}, overall: float, missing: ["EPS consensus figure"], flagged_gaps: [...]}。新增
  • ConflictLog 记录 Hand 间的冲突：{conflict_id, hands: [H_A, H_B], type: "temporal|methodological|source", resolution: "temporal_priority|uncertainty_flag|escalate"}。冲突类型 → 仲裁策略的映射可以从历史中学习。新增 
# OrchestrationLayer 的执行流程

def orchestrate(strategy: StrategyState, question: str) -> dict:
    plan = _build_plan(strategy, question)         # MDP → phase 1 hands

    for phase in plan.phases:
        configs = [_build_hand_config(h, strategy) # strategy → per-hand params
                   for h in phase.hands]
        results = await _run_hands(configs)         # 并行执行

        evals = [_evaluate_hand(r, strategy.evaluation_dims)
                 for r in results]               # 策略特定维度评分

        conflicts = _detect_conflicts(results)      # 冲突检测 + 分类

        # Lazy evaluation: 若置信度已足够，跳过后续 phases
        if _synthesis_confidence(evals) >= strategy.confidence_threshold:
            break

    return OrchestrationResult(results, evals, conflicts, plan)
4Layer 4

GoalContext — 目标上下文（跨 Session 积累）

当前 last-synthesis.md 是单条覆写的——每次 Brain synthesize 都会清空前一次。GoalContext 是多 session 持续积累的、以研判目标（goal）为单位的知识库。

📋

GoalContext

brain/goals/{goal_id}.json
  • goal_id 目标标识。例：market_research_NVDA_2026Q3、macro_scan_fed_jun2026、position_review_portfolio_q2。一个 goal 可以跨多个 session 持续。新增
  • status open（研究进行中）/ investigating（有初步结论，持续监视）/ concluded（已决策，归档）。状态转换由用户行为或 Brain 判断触发。新增
  • key_findings 从 Hand 结果和 synthesis 中积累的关键发现：[{finding_id, hand_id, claim, confidence, ts, superseded_by: null}]。新发现不覆盖旧发现，而是追加并标记是否取代。新增
  • synthesis_history Brain synthesis 快照列表（非覆写）：[{ts, stance, confidence, key_drivers, reversal_condition}]。保留历史，使 stance 变化轨迹可追溯，支持 Structured Prediction Calibration。新增
  • contradiction_log 跨 session 的持久化冲突记录。同一冲突（宏观 vs 微观分歧）如果反复出现，会被标记为"结构性不确定性"，Brain 应在 synthesis 中显式呈现。新增
  • context_summary Brain 定期（每次 synthesis 后）更新的目标状态摘要。替代当前 last-synthesis.md，但是累积的而非覆写的。作为下次 synthesis 的上下文输入。新增
关键升级：GoalContext 使 Brain 从"每次问、每次答"升级为"持续研究一个目标"。NVDA 的研判可以跨 10 个 session 积累，每次 synthesis 都在前次基础上更新，不是从头开始。这是 investment research 中 analyst 工作模式的真实写照——没有 analyst 每次研究一个标的都从零开始。
5Layer 5

DataFlywheel — 结构化原生数据与优化闭环

飞轮的核心不是"收集更多数据"，而是原生数据（native data）的结构化沉淀：Brain 在执行过程中自然产生的评估、判断和决策本身就是最有价值的训练信号，无需额外标注。

①

Episode 执行产生原生数据

每次 Brain synthesis 完成后，自动产生一条 FlywheelRecord，包含该 episode 中所有的结构化评估信号。

Brain 自评 synthesis 质量 Brain 对每个 Hand 的评分（按 EvalDimension） Hand 自报告（confidence, freshness, source tier） OrchestrationPlan 执行情况（哪些 phases 实际运行） 冲突类型 + 仲裁决策
②

Human-Agent 交互异步注入反馈

用户的后续行为（接受/修改 stance、strategy_edit、refine 某个 anchor、分享资源、提问跟进）通过 episode_id 关联到产生这些内容的 episode，成为 delayed feedback。

用户接受 stance（正信号） 用户修改 stance（负信号 + 方向） strategy_edit（what changed + why） refine/delete anchor（隐式质量信号） reversal_condition 触发（预测质量验证）
③

FlywheelAnalyzer 处理 → 提取优化信号

定期（或触发式）分析积累的 FlywheelRecord，提取三类优化信号：

IntentProfile 更新信号（信念变化、风格漂移） StrategyState 更新信号（哪些维度真正有预测力） Hand 质量信号（哪些 Hands 在哪类问题上 load-bearing）
④

更新 Layer 1–2 → 下次 episode 更优

优化信号被应用回 IntentProfile（belief_state 更新、intent velocity 调整）和 StrategyState（evaluation_dims 权重更新、source_weights 调整、research_priorities 重排）。

IntentProfile.belief_state 更新 StrategyState.evaluation_dims 权重更新 StrategyState.source_weights 调整 GoalContext.synthesis_history → calibration 
@dataclass
class FlywheelRecord:
    episode_id:   str
    goal_id:      str
    ts:           str
    plan_id:      str                   # 关联 OrchestrationPlan

    # 原生评估数据（episode 结束时自动产生）
    brain_self_eval:    BrainSelfEval      # synthesis 质量自评
    hand_evaluations:   dict[str, HandEval] # {hand_id: dim_scores + gaps}
    hand_self_reports:  dict[str, dict]    # Hand 自报告质量信号
    orchestration_trace: list[dict]       # 实际执行的 phases + 触发条件

    # 延迟注入（async，通过 episode_id 关联）
    human_feedback: list[HumanFeedback]   # intent capture 中关联的反馈

    # 派生优化信号（FlywheelAnalyzer 计算）
    profile_signals:   list[ProfileSignal]  # → IntentProfile 更新
    strategy_signals:  list[StrategySignal] # → StrategyState 更新
为什么叫"原生数据"：FlywheelRecord 不是衍生指标（"reward = 0.73"），而是 Brain 和 Hand 在执行过程中自然产生的决策记录——仲裁了什么冲突、哪个 EvalDimension 没被满足、用户在多久之后修改了 stance。这些数据是可审计的、可解释的、可直接用于下一步改进的，不是黑盒 reward 数字。

→实施阶段

分阶段实施路径

BrainStateEngine 是一个增量演化的架构，不需要一次性重写。现有组件继续工作，新层在旁边生长。

P0

基础设施（1 周）— 数据骨架先行

  • Episode identity 传递（brain synthesis → episode_id → card data-attribute → intent capture）
  • GoalContext 骨架（goal_id + status + synthesis_history 替代 last-synthesis.md）
  • FlywheelRecord 结构定义 + JSONL 写入（比当前 reward_ledger 更丰富的字段）
  • Canvas→Brain 路径打通（canvas generate 时 POST /analyze）
P1

评估层升级（2 周）— 使飞轮信号有意义

  • Evaluator 升级：词袋 → LLM-as-judge（异步，不阻塞主流程）
  • StrategyState 第一版：从 IntentWiki + BrainState.rules 派生（非 ML，基于规则）
  • EvalDimension 第一版：手工定义每类 Hand 的核心验证维度（earnings_hand 必须有 EPS 数字等）
P2

意图画像（3 周）— Brain 开始"认识"用户

  • IntentProfile 第一版：从 IntentStream 历史推断 belief_state + analytical_style
  • GoalContext key_findings 积累 + 跨 session 更新机制
  • FlywheelAnalyzer 第一版：提取 profile_signals（用户接受/修改 stance → belief 更新）
P3

编排升级（4 周）— Hand 开始有策略地执行

  • HandConfig：StrategyState → per-hand 参数（focus、depth、look_for）
  • OrchestrationPlan MDP（phase 1 必须 + phase 2+ 按置信度触发的 lazy evaluation）
  • ConflictLog + 冲突类型分类（temporal / methodological / source）
  • Structured Prediction Calibration（200+ episodes 后，stance/confidence ECE 评估）
P4

飞轮闭合（后续）— 从数据到自优化

  • FlywheelAnalyzer 完整版：strategy_signals → StrategyState.evaluation_dims 权重自动更新
  • Cross-Source Calibration（regime-dependent source weights，500+ episodes 后）
  • Similar past questions retrieval（向量检索历史 goals + syntheses）
  • OrchestrationPlan 学习（哪种编排顺序对哪类问题效果最好）
