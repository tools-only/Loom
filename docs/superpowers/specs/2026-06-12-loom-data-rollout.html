业务流程全链路

一次 POST /analyze 请求在系统内经历的完整旅程，从路由决策到反馈写回。

1

WorkflowResolver

domain_hint → keyword match → LLM 分类；产出 {domain, mode, hands[]}

2

Prompt Assembly

BrainState.query_rules + frameworks + intent stream tail(5) + IntentWiki 激活 + RewardedIntent 政策 → 7 层 system prompt

3

B-Plan

BrainHarness.plan() 写 analysis rubrics（分析维度），非 per-hand 分配；一次 LLM call

4

Hand Dispatch

market / sentiment / target / position 并行执行；每 hand 自主决策 fetch_resource / web_search / fetch_url

5

B-Review

BrainHarness.review() 检查 rubric 覆盖；confidence_gaps + follow_up 决策

6

Synthesize

stance / confidence / key_drivers / reversal_condition；variable-overlap gate 精筛 frameworks

7

Auto Reward + Flywheel

evaluate_and_update() 立即运行；FlywheelRecord.new() 写 episode；write_last_synthesis()

8

Presentation + Intent

compose_presentation() 组装 cards/detail_panels；intent event 追加到 stream + IntentWiki

Prompt 7 层结构（BrainHarness._assemble_prompt）

① brain.md 静态角色合约（identity, not data） →  ② brain-coordination SKILL 元技能索引（静态） →  ③ BrainState.query_rules(domain) 策略规则（Python 侧过滤，非批量加载） →  ④ query_frameworks(domain, hand_claims) 分析框架（variable-overlap gate：只有 hand claims 含相关变量才纳入） →  ⑤ intent_stream.tail(5) 最近 5 条用户意图事件（用户的 WHY） →  ⑥ IntentWiki.activate() 长效意图节点激活（zone 分类 + confidence） →  ⑦ RewardedIntentHarness.format_plan_for_prompt() 已选政策作为生成约束

Brain 模块架构

Brain（port 3002）是系统的决策核心，不执行具体数据获取，只负责策略路由、任务分解、综合分析与学习更新。

BrainHarness loom/brain_harness/base.py

Brain 的核心编排层，管理 prompt 组装、三段式 LLM 调用（plan/review/synthesize）和 presentation 构建。

1
plan(question, workflow_decision)写分析维度（rubrics），不分配 per-hand 任务。
2
review(question, analysis_plan, hand_artifacts)检查 rubric 覆盖率，产出 confidence_gaps 和 follow_up_tasks。
3
synthesize(question, hand_artifacts, ...)汇总 hand key_claims → stance / confidence / key_drivers / reversal_condition。综合后立即触发 evaluate_and_update()。
4
compose_presentation(synthesis, hand_artifacts)构建 overview / cards[] / detail_panels{} / quality_gaps[]，供 UI 渲染。

WorkflowResolver brain_harness/dispatcher.py

domain-aware hand 调度策略。优先级：caller hint → keyword match → LLM 分类。

hint
context["domain_hint"]调用方直接传 domain，跳过所有推断。
kw
workflows.json trigger_keywords正则 scan 问题文本，内置 + user overrides（brain/personal/workflows.json）合并生效。
llm
LLM fallback 分类一次廉价 LLM call；mode = full_fanout（全部相关 hand）或 dynamic（按 hands_pool）。

GoalContext brain_harness/goal_context.py

  • GoalContext 对象per-goal 研究生命周期：goal_type（market_research / position_review / target_tracking / ad_hoc）、status（open / investigating / concluded）
  • key_findings[]Finding：claim + hand_id + confidence + episode_id + tags；upsert by finding_id
  • synthesis_history[]SynthesisSnapshot：episode_id · stance · confidence · key_drivers · reversal_condition；保留最近 20 条
  • contradiction_log[]记录两个 hand 之间的相互矛盾（hand_a / hand_b / description / resolved）
  • 持久化每个 goal 一份 JSON：brain/goal_context/{goal_id}.json，GoalContextStore 管理 CRUD

ResourceDistiller brain_harness/distiller.py

把外部资源（RSS 文章、研报）蒸馏为可检索的 AnalyticalFramework，写入 brain/personal/frameworks.json。

→
POST /distill输入 resource_url / source_author，同步追加 IntentEvent（resource_share 类型）到 intent-stream。

BrainState — 三层可查询数据

Brain 侧唯一的结构化状态存储。所有选择逻辑在 Python 进程运行，只有命中的条目进入 LLM prompt，这是 Brain harness 与 Hand harness 的核心结构差异。

Strategy Rules Frameworks Learned Notes

LearnedNote：timestamp · domain · note · tags[]。

query_notes(domain, n=5)：返回该 domain 最近 n 条笔记，注入 prompt 第 ③ 层之后。

这是 Learner（Stage 3）的输出面 — 高价值 correction 总结后写入此处，下次 synthesize 自动生效。

Intent Stream brain/context/intent-stream.jsonl

turn-level 用户意图事件。每次 /analyze 结束后异步追加（IntentProcessor.parse() → IntentEvent）。

tail(5)：最近 5 条事件作为"用户的 WHY"注入 prompt 第 ⑤ 层。

⚠ 当前缺口：只记录 human input，agent output turn 未写入 → CorrectionDetector 无法建立 turn pair。

human input only

Intent Wiki brain/intent_wiki/intents.json

长效用户意图节点，按 8 个 zone 分类：content_requirements / decision_style / workflow_preferences / source_preferences / object_behavior / risk_sensitivity / personal_style / domain_principles。

每次 ingest_event 更新 confidence + evidence_count。activate(question, domain) 产出 IntentActivation（active_intents[]），供 RewardedIntentHarness 使用。

8 zones confidence 0–1

Last Synthesis Snapshot brain/context/last-synthesis.md

最近一次综合结果的 Markdown 快照，BrainHarness.write_last_synthesis() 在每次 synthesize 后写入。

仅在文件 mtime < 24h 时自动注入 prompt（第 ⑦ 层之后），提供跨 session 的上下文连续性。

24h TTL auto-expire

Auto Reward — RewardedIntentHarness

每次 synthesize 后自动运行，三段：Policy Planning（选政策）→ Evaluation（6 维评分）→ Credit Assignment（更新权重）。

Policy Planning

根据激活的 Intent zones 选政策，注入 Brain prompt 最后一层作为执行约束。

1
IntentWiki.activate(question, domain)返回 IntentActivation：active_intents[]（含 zone / label / confidence）。
2
plan(activation, domain, question, limit=5)遍历政策，score = weight + 0.12×|matched_zones|，取 top-5 selected，写 episodes.jsonl。
3
format_plan_for_prompt(plan)格式化为"执行约束"注入 system prompt，LLM 必须遵循（非背景记忆）。

Evaluation & Credit

synthesize 完成后立即自动评估，结果反向更新政策权重。

1
evaluate_and_update(activation, plan, synthesis, hand_artifacts)6 个 evaluator，产出 evaluator_scores{}（每个 0-1）。
2
policy_rewards 聚合每条政策的分数 = 其 reward_targets 对应 evaluator 分的均值。
3
_update_policy_weights()w ← clamp(w + 0.08×(r−0.5), 0.15, 0.95)；average_reward 用 running mean 更新。
4
credit_assignments.jsonl每条政策：credit = positive(≥0.6) / negative(<0.45) / neutral，附 reason（diagnosis 文本）。

6 维自动评分

intent_coverage

意图覆盖率

active_intents 的关键词在输出文本中的命中比例。

0.25 + 0.75 × hits / len(intents)
relevance

相关性

用户问题关键词命中率；intents 过多时轻微惩罚 −0.08。

clamp(0.35 + 0.55 × q_hits/q_words, 0.1, 0.9)
freshness

新鲜度

若 intent 需要 recent context，检查输出中是否有新鲜度信号。

0.82 if fresh_signal else 0.28
risk_coverage

风险覆盖

intent zones 含 risk_sensitivity 时，统计风险词命中数。

clamp(0.25 + hits × 0.16, 0, 0.9)
decision_usefulness

决策可用性

输出结构性：stance 明确 / key_drivers / reversal_condition 各加分。

0.35 +0.18×stance +0.18×drivers +0.14×reversal +0.1×conf
style_fit

风格匹配

P0 固定 0.55（占位）；P4 由 FlywheelAnalyzer 基于历史行为动态推断。

0.55 static (P0)

Detection & Learning Loop

从反馈采集到行为改变需要 4 个环节。Detector 只产生带置信度的结构化信号，不直接写策略。

1

Detect（Stage 2，规划中）

CorrectionDetector 扫描 intent-stream 相邻 turn pairs，分类"用户是否在纠正上一轮 agent 输出"，提取 correction_text + agent_claim + confidence。前提：intent-stream 补齐 agent output turn。

2

Normalize（结构已就位）

无论来自 UI widget 还是 detector，事件整理为统一 feedback schema。差异只在 source（ui_feedback / correction_detector）和 confidence 字段，消费方逻辑不变。

3

Auto Aggregate（已实现，每次 synthesize）

RewardedIntentHarness.evaluate_and_update()：6 维评分 → policy_rewards → credit assignment → policy weight EMA 更新。这个环节无需等待 Stage 1/2，现在即运行。

4

Apply（Stage 3，规划中）

把高价值 correction 写回 learned-notes.json、资源排序（resource_tier weighting）或 strategy.md，让 hand 在下次执行前真正读到变化。FlywheelAnalyzer（P4）派生 profile_signals / strategy_signals。

Boundary Rules

  • Detector 不直接更新策略只产生带置信度信号，避免单次误判直接污染 hand 行为。
  • Stores stay append-only所有原始事件保留；权重、过滤与总结放在消费者层完成。
  • Learning outputs must be readable至少 learned notes 或 episode record 必须可被操作者和 hand 双重消费。
  • Confidence affects weighting, not persistence低置信度事件保留，但不与显式用户纠正等权处理。
  • UI layer stays thin前端只发事件，不承担 detector、学习或聚合逻辑。
  • Auto reward already live (P0)RewardedIntentHarness 在 synthesize 后立即运行，无需等待任何人工操作。
