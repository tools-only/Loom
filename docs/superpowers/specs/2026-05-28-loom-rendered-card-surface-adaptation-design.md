# Loom rendered card surface adaptation design

## Goal

Adapt the cards rendered inside Loom's HTML content canvas to the softer visual language established in `resource/ui_kits/report/index.html`. The change targets generated document surfaces only: large content sections should feel lighter and more translucent, while nested information cards keep readable, quiet pastel gradients.

## Scope

The implementation applies only inside `#anchor-content`, the container populated by `bridge/webview/anchor-client.js`.

In scope:

- Outer generated sections using `.anc-section--gc`
- Nested generated sections inside a report or domain page
- KPI cards using `.anc-kpi` and existing tone modifier classes
- Feed and domain content cards using `.blog-card` with existing section tone modifiers
- Responsive and regression verification for rendered content cards

Out of scope:

- The home surface, prompt suggestions, command center, question lab, or domain entry cards
- Toolbar, navigation tabs, workspace panel, context panel, timeline panel, or inbox shell
- Changes to Anchor protocol attributes, rendering commands, patch behavior, or hash routing
- New report template variants or additional theme galleries
- Refactoring the static report template into a shared stylesheet during this change

## Current State

The dynamic HTML canvas already accepts a common component vocabulary: `.anc-section`, `.anc-section--gc`, `.anc-kpi`, `.anc-kpi-grid`, and tone classes such as `aurora`, `ocean`, `warm`, `cool`, `arctic`, `berry`, and `flame`. The webview style sheet also contains `card1.html`-inspired gradients for generated content and separate home-screen styling.

The static report template demonstrates a calmer treatment: outer panels are visually restrained and the colored information cards use shallow corner color washes over a predominantly light surface. This approved language should become the visual baseline for dynamically rendered cards without changing generated HTML markup.

## Chosen Approach

Use scoped CSS adaptation in `bridge/webview/styles.css`.

The implementation preserves the existing generated markup and all Anchor interaction behavior. It changes presentation rules beneath `#anchor-content` so content generated by the agent, overview routes, and domain routes share the same relaxed card character automatically.

This approach is preferred over modifying `anchor-client.js`, because agent-supplied HTML can already contain the existing component classes. It is preferred over extracting shared template assets because the current request is a focused webview adaptation, not a design-system restructuring.

## Surface Hierarchy

### Outer generated sections

Large top-level `.anc-section--gc` surfaces use translucent milky white instead of solid white:

- A light white overlay in roughly the `0.62` to `0.76` opacity range
- Subtle cool or mint ambient washes at the edges
- A low-contrast white border and restrained shadow
- Only modest hover lift so large document sections remain stable while reading

The translucency lets Loom's ambient workspace background remain visible without making prose compete with the backdrop.

### Nested sections

Nested `.anc-section` elements use a slightly more opaque neutral surface than their parent. This preserves a clear reading layer when generated reports contain subsections, tables, or long analysis blocks.

### KPI and information cards

`.anc-kpi` cards and tone-modified `.blog-card` elements carry the report template's primary color expression:

- A very light center and soft color concentrations at the corners
- The existing tone names remain valid so generated HTML does not change
- Strong or warning semantics remain distinguishable through the relevant warm and flame families
- Shadows stay shallow and pill-like rather than producing elevated dashboard tiles

No new card class contract is introduced. Existing generated content continues to work.

## Interaction And Protocol Behavior

This is a presentation-only adaptation.

- `data-anc`, `data-handles`, and patch targeting remain unchanged.
- Handle triggers, popup menus, annotations, lock states, timeline rendering, and routing remain unchanged.
- Existing content generation prompts do not need new class names.
- Focus and interaction affordances must remain readable against translucent section backgrounds.

## Verification

The implementation must verify:

1. CSS regression tests cover a translucent outer generated section surface and maintain gradient card coverage.
2. Existing KPI grid responsiveness remains intact.
3. A Loom content route rendered in the browser displays readable translucent outer panels and calm pastel inner cards at desktop width.
4. The same route remains readable on a narrow viewport with cards stacking correctly.
5. No home-shell components are included in the changed style selectors or altered by the adaptation.

## Constraints

- Keep all changes scoped beneath `#anchor-content` where new visual rules affect generated content.
- Preserve current component class names and rendered HTML contracts.
- Do not change the static report artifact as part of implementing this adaptation.
- Do not add JavaScript for styling behavior.
