Brain 侧状态管理 + AgentOps 方案 · v0.2

BrainStateEngine
动态状态管理层

将现有 BrainState / IntentWiki / IntentStream / RewardHarness 等碎片化组件统一为一个有明确推导链的状态引擎，并把 Hand Agent 管理纳入同一闭环——从用户意图出发，推导策略与 AgentPolicy，策略指导 Hand 编排，执行结果沉淀为目标上下文与能力缺口，全链路数据进入飞轮持续优化意图、策略、workflow 与 agent 能力资产。

5+1状态层级 + AgentOps
L1→L2→L3意图到编排推导链
L4→L5→AgentOps能力演化链
P0 已落地GoalContext + Flywheel

为什么现有架构不够

现有组件各自为政，没有推导关系。

现状问题

  • BrainState 存放策略规则和框架，但不知道用户当前意图是什么
  • IntentWiki 维护长期意图图，但不会转化为 Hand 执行策略
  • IntentStream 记录意图事件流，但下游不读它
  • RewardHarness 有奖励信号，但无法回写到意图或策略结构
  • 每次 /analyze 都是无状态的——上一次研判的结论不影响本次 Hand 编排
  • 没有跨 episode 的目标上下文，不能积累"这支票我已经研究了三周"的状态

BSE 解决什么

  • 推导链：IntentProfile → StrategyState → HandConfig，三者有明确因果关系
  • 积累链：每次 synthesis 写入 GoalContext，跨 session 保留研判历史
  • 可验证评估：EvalDimension 给每个 Hand 定义布尔可验证维度，取代模糊关键词匹配
  • 数据飞轮：Brain 自评 + Hand 评估 + 人工反馈 → FlywheelRecord → 优化 L1/L2
  • State-Driven AgentOps：从 GoalContext 与 FlywheelRecord 中识别能力缺口，驱动 AgentRegistry、WorkflowRegistry 与 AgentPolicy 演化
  • episode_id 链：每次 /analyze 绑定 episode，从 UI 卡片到后端记录全程可溯

在整体 Loom 架构中的位置

BSE 完全在 LoomBrain :3002 内部，不对外暴露接口，通过 Brain Harness 影响 Hand 调用、workflow 编排、agent 能力演化和 synthesis 质量。

L1
IntentProfile P2 实现

动态用户意图画像

从行为中动态推断用户意图，比 IntentWiki 的显式声明更实时、更细粒度。是整个推导链的起点。

核心职责

  • active_intents：当前激活的意图节点列表，每个节点有置信度和证据计数
  • belief_state：对特定资产/主题的当前信念（看多/看空/中性 + 强度）
  • analytical_style：用户偏好的分析风格（基本面/技术/宏观 + 详略程度）
  • intent_velocity：意图变化速率——高速说明用户正在快速形成新判断
  • domain_focus：当前关注的市场领域（A股/美股/宏观/个股）

更新触发器

  • 每次 /intent/capture 事件 → 更新 active_intents
  • L5 飞轮信号 profile_signals → 调整 belief_state
  • 用户在 canvas 上的 op 行为 → 调整 analytical_style

数据结构

@dataclass
class IntentNode:
    zone: str          # 8 个 IntentWiki zone
    label: str
    principle: str
    confidence: float
    evidence_count: int = 0

@dataclass
class IntentProfile:
    profile_id: str
    updated_at: str
    active_intents: list[IntentNode]
    belief_state: dict[str, BeliefRecord]
    analytical_style: StyleRecord
    intent_velocity: float   # 0-1
    domain_focus: DomainFocus

持久化

  • 文件：brain/intent_profile/current.json
  • 历史快照：brain/intent_profile/history.jsonl
  • P2 阶段：由 IntentWiki 节点初始化，逐步迁移
L2
StrategyState P1 实现

基于意图的策略状态

由 IntentProfile（L1）自动推导。定义当次研究的优先级、信息策略、AgentPolicy，以及对各 Hand 结果的可验证评估维度（EvalDimension）。

核心职责

  • research_priorities：本次最重要的问题列表，按 L1 意图权重排序
  • information_strategy：哪些 Hand 必须跑、哪些可选、哪些互斥
  • AgentPolicy：定义何时保留、重编排、拓展、新建或淘汰 agent
  • AgentSelectionPlan：从 AgentRegistry 中选择本次 workflow 的候选 agent 与 fallback
  • EvalDimension：针对每个 Hand 的可验证评估维度——布尔检查，非关键词包
  • framework_ids：本次应激活的分析框架 ID 列表
  • confidence_threshold：合成置信度阈值，低于此值触发 Lazy Evaluation 追加
  • position_logic：仓位决策逻辑规则（当有仓位相关意图时）

EvalDimension 设计

  • 每个 Hand 对应 2-5 个 EvalDimension
  • 每个维度有：verify（自然语言判断规则）、weight（权重）、required（必填）
  • Brain 在 synthesis 后对 Hand artifact 逐维度打分，写入 L5

数据结构

@dataclass
class EvalDimension:
    dim_id: str
    hand_id: str
    label: str    # e.g. "提供EPS数据"
    verify: str   # 判断规则（prompt给Brain）
    weight: float
    required: bool = False

@dataclass
class StrategyState:
    strategy_id: str
    goal_id: str
    derived_from_profile: str
    research_priorities: list[str]
    information_strategy: InfoStrategy
    agent_policy: AgentPolicy
    agent_selection_plan: AgentSelectionPlan
    evaluation_dims: list[EvalDimension]
    framework_ids: list[str]
    confidence_threshold: float = 0.65

  • P1 用规则推导（基于 IntentWiki active nodes）
  • P2 升级为从 IntentProfile 推导
  • 文件：brain/strategy/current.json
L3
OrchestrationLayer P3 完整 MDP

Agent 编排、评估与运行时管理

用 StrategyState（L2）驱动 Hand Agent 的调用顺序、运行时配置和 workflow 选择，实现多阶段 MDP 编排。同时持有 ConflictLog 与 AgentManagementDecision，记录 Hand 间分歧、能力缺口和编排调整建议。

核心职责

  • Phase 0 — 必调：strategy.required_hands 中的 Hand 无条件先跑
  • Phase 1 — 置信评估：Brain 对 Phase 0 结果评估合成置信度
  • Phase 2 — 懒惰评估：置信度低于 threshold → 追加 optional hands
  • AgentRegistry 查询：从结构化能力账本中选择 agent，而不是依赖硬编码 WorkflowResolver
  • AgentRuntimeConfig 生成：把 L2 策略转成每次调用的 phase、weight、fallback 和 context 注入
  • EvalDimension 打分：对每个 Hand artifact 按 L2 定义的维度逐项打分
  • 信息级联：Hand A 的输出可注入 Hand B 的 query context（条件查询）
  • 冲突识别：时序冲突 / 方法论冲突 / 数据重叠冲突 → 写入 ConflictLog
  • 分歧即信号：高分歧 → 合成结论加紧反转条件

Star 拓扑 vs Mesh 拓扑

  • Brain 是星形中心：所有 Hand 间通信都经过 Brain
  • 不允许 Hand 直接调用 Hand（无 mesh peer-to-peer）
  • Brain 持有全局视图，可做跨 Hand 冲突仲裁

数据结构

@dataclass

AO
State-Driven AgentOps P1.5 / P2.5 / P4 扩展

由状态驱动的 Agent 管理与能力演化

AgentOps 不是独立系统，而是 BSE 的控制面扩展。Brain 基于 L1 用户意图、L2 策略、L4 目标积累和 L5 执行反馈，判断是否需要调整 agent、拓展 agent、新建 agent 或重编排 workflow。

核心职责

  • AgentRegistry：记录所有 hand agent 的能力、schema、版本、风险等级、状态和评估维度
  • WorkflowRegistry：记录长期目标中稳定复用的 agent 编排模板
  • CapabilityGapState：从 GoalContext 和 FlywheelRecord 中提取反复出现的能力缺口
  • AgentEvolutionPolicy：约束 brain 何时允许调参、拓展、新建或淘汰 agent
  • AgentManagementDecision：把状态诊断结果转为可执行的 registry/workflow patch

决策闭环

  • Observe：读取用户输入、goal 状态、agent 输出、人工反馈
  • Diagnose：判断问题属于参数不合适、编排不合适、能力缺失或 agent 边界错误
  • Decide：选择 keep / reconfigure / tune / extend / create / retire
  • Execute：由 Agent Manager 更新 registry 或生成 workflow patch
  • Evaluate：下一轮执行后把效果写回 FlywheelRecord

数据结构

@dataclass
class CapabilityGap:
    gap_id: str
    goal_id: str
    description: str
    evidence_episode_ids: list[str]
    missing_capability: str
    related_agents: list[str]
    repeated_count: int
    severity: float
    reuse_score: float
    suggested_action: str

@dataclass
class AgentEvolutionPolicy:
    create_gap_count: int = 3
    same_failure_count: int = 2
    reuse_score_min: float = 0.6
    require_persistent_goal: bool = True

关键原则

  • Brain 管理 AgentSpec 和 workflow，不直接管理 hand agent 内部 subagents
  • 新 agent 必须先进入 experimental 状态，再通过评估转 active
  • 能力演化来自重复证据，不来自单次 prompt 冲动
  • 高风险领域的 agent 创建、替换和外部动作必须要求用户确认
L4
GoalContext P0 已实现 ✓

基于目标的积累上下文

每个研究目标（如"研判 NVDA"）对应一个 GoalContext，跨 session 积累 findings、synthesis 快照、矛盾记录和能力缺口线索。取代单次写入的 last-synthesis.md。

核心职责

  • key_findings：各 Hand 的关键判断，按置信度排序，跨 session 积累
  • synthesis_history：历史整合快照（最近 20 条），保留 stance 变化轨迹
  • contradiction_log：跨 episode 的矛盾记录，支持后续仲裁
  • capability_gap_hints：记录用户反复要求但当前 workflow 无法稳定满足的能力缺口线索
  • context_summary：Brain 维护的目标摘要字符串，注入下次 synthesis prompt
  • episode_ids：本目标所有 episode 的 ID 列表，链接到 L5
  • status：open → investigating → concluded 三态

与 last-synthesis.md 的区别

  • last-synthesis.md 是单文件覆盖写，无历史
  • GoalContext 保留完整历史，支持 stance drift 追踪
  • 多目标并存（NVDA 目标 + 宏观目标 同时维护）
  • 目标可被 conclude，不污染 active 目标的上下文

L5
DataFlywheel P0 写入已实现 ✓ P4 分析器

数据飞轮

每次 /analyze 产生一条 FlywheelRecord，沉淀 Brain 自评 + Hand 评估 + AgentPerformance + 人工反馈。P4 阶段 FlywheelAnalyzer 从中提取信号，回写优化 L1（意图）、L2（策略）和 AgentOps（registry/workflow）。

数据来源（三类原生数据）

  • Brain 自评（brain_self_eval）：synthesis 置信度、stance、key_driver 数量、是否 cold_start
  • Hand 评估（hand_evaluations）：每个 Hand 的 artifact 质量：claim 数量、gap 数量、数据源层级（Tier A/B/C/E/F）
  • Agent 表现（agent_performance）：每个 agent 的成功率、失败类型、延迟、成本、fallback 次数和 schema 适配问题
  • 人工反馈（human_feedback，异步注入）：thumbs_up / thumbs_down / correction / ignore + 可选纠正意见

飞轮回路（P4）

  • FlywheelAnalyzer 批量读取 records.jsonl
  • 归因：哪些 Hand + 哪种 Intent 组合 → 高置信度合成
  • profile_signals → 更新 L1 active_intents 权重
  • strategy_signals → 更新 L2 evaluation_dims 和 Hand 权重
  • agent_signals → 更新 AgentRegistry、WorkflowRegistry 和 AgentEvolutionPolicy 阈值
  • feedback correction → 修正 belief_state
信号消费者缺口：无 LLM 微调的前提下，飞轮信号只能通过 prompt engineering 影响 Brain（调整 policy weights、pruning frameworks、Hand config 降权）。这是"弱信号作用于强先验"，改善空间受限但仍有价值。P4 阶段评估实际效果后决定是否引入外部微调。

设计约束

  • 所有持久化在 brain/ 目录下，不污染其他目录
  • 推导链（L1→L2→L3）是单向的，不允许反向写
  • 积累链（L4→L5→L1）通过 FlywheelAnalyzer 异步批量处理，不阻塞 /analyze
  • GoalContext 文件上限 20 条 synthesis_history（滚动）
  • FlywheelRecord JSONL 是 append-only，永不覆盖；detail JSON 仅 human_feedback 字段可追加
  • episode_id 格式：ep-{ts_ms}-{hex8}，全局唯一，无外部依赖
  • GoalContext goal_id 格式：goal-{ts_ms}-{hex6}
  • 不依赖任何新第三方库（仅 stdlib dataclasses/json/pathlib）
