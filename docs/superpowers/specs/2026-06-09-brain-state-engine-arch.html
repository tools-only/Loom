L1Layer 1

IntentProfile — 动态用户意图画像

Brain 从行为中主动推断和维护的用户模型。与 IntentWiki（用户显式声明）相对：IntentWiki 是人工种子，IntentProfile 是演化结果。

🧠

IntentProfile 新增

loom/brain_harness/intent_profile.py · brain/state/intent_profile.json
  • 📍 belief_state：Brain 追踪用户当前对各 topic 的信念状态。{"NVDA": {stance: "cautiously_bullish", confidence: 0.68, last_updated: "...", source: "strategy_edit"}}。当用户接受 buy stance、修改 strategy rule 或明确表达立场时更新。
  • ⚡ intent_velocity：意图变化速率 [0.0–1.0]。高 velocity（>0.7）表示用户正在调整视野，Brain 应减少 GoalContext 的惰性、更频繁刷新策略；低 velocity（<0.3）表示稳定期，GoalContext 可以积累更长时间再更新。
  • 🎨 analytical_style：从 anchor ops 学习的分析风格：density（expand ops 多 → 偏详细），framework_pref（哪类分析框架被频繁引用），risk_appetite（reversal_condition 是否经常被用户修改），time_horizon（问题里 near-term vs long-term 的比例）。
  • 🎯 domain_focus：当前关注层级。{primary: "market_research", secondary: ["macro", "sector_rotation"], ticker_watch: ["NVDA", "MSFT", "TSM"]}。从 query_patterns 和 intent_stream 中推断。 
@dataclass
class IntentProfile:
    profile_id:       str
    updated_at:       str
    # 从 IntentWiki 种子 + 行为推断的合并意图列表
    active_intents:   list[IntentNode]          # zone/label/confidence/evidence_count
    belief_state:     dict[str, BeliefRecord]     # {topic: stance+confidence+source}
    analytical_style: StyleRecord                   # density/framework_pref/risk_appetite
    intent_velocity:  float                       # 意图漂移速率
    domain_focus:     DomainFocus                   # primary/secondary/ticker_watch

# 更新触发器 (IntentProfileUpdater)
class IntentProfileUpdater:
    def on_intent_event(self, event: IntentEvent) -> None:
        # strategy_edit → belief_state update + intent_velocity up
        # resource_share → domain_focus update + framework_pref
        # stance accepted → belief_state confidence up
        # reversal triggered → belief_state reversal, velocity up
        ...
与 IntentWiki 的边界：IntentWiki 节点由用户主动编辑，是最高优先级的显式意图声明；IntentProfile 从行为中推断，置信度随证据累积增长。冲突时 IntentWiki 优先。IntentProfile.active_intents = IntentWiki 节点（高置信度种子）+ 推断节点（中低置信度）的并集。
更新触发器
  • 用户接受 Brain synthesis stance
  • strategy_edit 事件（belief 变化信号）
  • reversal_condition 被用户标记触发
  • anchor expand/shorten 频率（density 偏好）
  • resource_share 来源类型（framework_pref）
读取时机
  • StrategyState 派生前（L1 → L2）
  • BrainHarness._assemble_prompt() 构建时
  • GoalContext 创建新 goal 时
  • DataFlywheel 提取 profile_signals 后
L2Layer 2

StrategyState — 从意图派生的可执行策略

StrategyState 是 Brain 根据当前 IntentProfile 为当前 goal 生成的"行动纲领"。它不是静态规则文件，而是动态派生的执行计划，核心是为每类 Hand 定义可验证的评估维度。

🗺️

StrategyState 新增

loom/brain_harness/strategy_state.py · brain/state/strategy_{goal_id}.json
  • 🔬 research_priorities：基于 IntentProfile.belief_state + domain_focus 派生的当前研究重点，按优先级排序。例：["NVDA Q3 earnings quality", "AI capex cycle sustainability", "Fed path Q4 2026"]。
  • 📡 information_strategy：信息关注策略，派生自 IntentProfile.analytical_style + IntentWiki.source_preferences。包含：source_weights（各 Hand 的重要性权重）、recency_requirement（实时/日/周）、signal_focus（重点关注的信号类型）。
  • ✅ evaluation_dims（核心创新）：策略为每类 Hand 定义具体的、可验证的评估标准。例：{hand:"earnings_hand", dim:"has_eps_consensus", verify:"key_claims contains numeric EPS figure", weight:0.8}。这使评估从通用词袋升级为策略特定的结构验证。
  • 📐 position_logic（仓位管理模式）：维护各头寸的存续逻辑、持有条件和退出准则。{NVDA: {thesis: "AI capex 长周期受益", hold_condition: "capex guidance 维持", exit_trigger: "两季度 EPS miss >10%"}}。 
@dataclass
class EvalDimension:
    dim_id:   str
    hand_id:  str
    label:    str          # "提供当前 EPS consensus 数字"
    verify:   str          # 可执行的验证逻辑 (Python expression or prompt)
    weight:   float         # 在 synthesis quality 评估中的权重
    required: bool = False  # True = 缺失则评估失败，不只是降分

@dataclass
class StrategyState:
    strategy_id:          str
    goal_id:              str
    derived_from_profile: str          # profile_id + snapshot_ts
    updated_at:           str
    research_priorities:  list[str]
    information_strategy: InfoStrategy  # source_weights + recency + signal_focus
    evaluation_dims:      list[EvalDimension]
    framework_ids:        list[str]    # 从 BrainState.frameworks 中选取
    position_logic:       dict         # {ticker: PositionLogic} 仓位管理模式专用
    confidence_threshold: float = 0.65 # 触发 lazy evaluation 停止的阈值
EvalDimension vs 当前 词袋评估器：当前 _score_intent_coverage() 用正则匹配关键词，任何问题都用同一套词表。StrategyState 在"研究 NVDA 盈利质量"这个 goal 下，为 earnings_hand 定义 has_eps_consensus_number（必须有具体数字）、has_guidance_language（必须有 guidance 表述）、covers_q3_period（时间范围正确）等维度——这是布尔型的、与策略直接相关的验证，精度质变。
派生逻辑（P1 阶段：规则）
  • domain_focus.ticker_watch → research_priorities 第一条
  • source_preferences zone → information_strategy.source_weights
  • risk_sensitivity zone → EvalDim: has_reversal_condition
  • analytical_style.density → framework 选取数量
派生逻辑（P4 阶段：飞轮驱动）
  • EvalDim 权重来自历史 dim_scores 的预测力统计
  • source_weights 来自 Cross-Source Calibration
  • confidence_threshold 来自历史 synthesis 质量分布
  • framework_ids 来自 framework utility estimation
L3Layer 3

OrchestrationLayer — MDP 多步 Hand 编排

不是"选哪些 Hands"（单步 bandit），而是"以什么顺序、附带什么上下文、在什么条件下触发下一 phase"（MDP）。Brain 是编排的控制器，每步决策都基于已积累的 Hand 输出状态。

⚙️

OrchestrationLayer 新增

loom/brain_harness/orchestration.py
  • 📝 HandConfig 生成：StrategyState → 为每个 Hand 生成具体任务参数。{hand_id: "earnings_hand", focus: "Q3 EPS vs consensus + guidance language", depth: "deep", time_window: "90d", look_for: ["consensus_eps", "guidance_revision", "margin_trend"], exclude: ["noise_signals"]}。Hand 接收 config 后可调整 query 策略，而不是总用相同的默认参数。
  • 🔀 MDP 编排计划：Phase 1（必须执行）→ 测量 synthesis 置信度 → Phase 2（条件触发）→ … 。例：phase_1: [macro, fundamental], condition: "confidence < 0.65", phase_2: [sector], condition: "conflict_detected", phase_3: [verification]。支持 Lazy Evaluation：置信度达阈值则不启动后续 phase，节省 API 成本。
  • ⚡ 冲突检测 + 仲裁：对比所有 Hand 输出，识别三类冲突：temporal（宏观领先指标 vs 近期微观数据，时间维度不同）、methodological（技术面 vs 基本面，方法论不同）、source_overlap（多个 Hands 引用同一数据源，分歧是虚假的）。每类冲突对应不同的仲裁策略，仲裁结果写入 ConflictLog。
  • 📊 Hand 评估（EvalDimension 驱动）：对每个 Hand 的结果按 StrategyState.evaluation_dims 逐维度评分，产生 HandEvaluation：{hand_id, dim_scores: {dim_id: 0|1|0.5}, overall: 0.82, missing: ["eps_consensus_number"], flagged_gaps: [...]}。missing 字段直接告诉 Brain 哪个信息缺口需要追问或降低对该 Hand 的信任度。 
# OrchestrationLayer 主执行流
async def orchestrate(self, strategy: StrategyState, question: str, goal: GoalContext):
    plan = self._build_plan(strategy, question)           # → OrchestrationPlan (phases)
    state = OrchestrationState(plan=plan, results=[], evals=[], conflicts=[])

    for phase in plan.phases:
        # 1. 生成每个 Hand 的 config（策略驱动）
        configs = {h: self._build_config(h, strategy, state) for h in phase.hands}

        # 2. 执行（并行 + 信息级联：前 phase 输出作为后 Hand 上下文）
        results = await asyncio.gather(*[self._run_hand(h, configs[h], goal) for h in phase.hands])
        state.results.extend(results)

        # 3. 冲突检测 + 分类
        conflicts = self._detect_conflicts(results)
        state.conflicts.extend(conflicts)

        # 4. 按 EvalDimensions 评分
        evals = [self._evaluate(r, strategy.evaluation_dims) for r in results]
        state.evals.extend(evals)

        # 5. Lazy Evaluation: 若 synthesis 置信度已足够 → 停止
        conf = self._estimate_synthesis_confidence(state)
        if conf >= strategy.confidence_threshold and not conflicts.has_unresolved:
            break

    return OrchestrationResult(state)
信息级联（Information Cascade）：当 phase 1 的 macro_hand 输出"Fed 维持利率概率 78%，市场充分 price in"时，Brain 可以在启动 phase 2 的 sector_hand 时注入这个上下文：config.extra_context = "Fed path confirmed stable; focus on rate-insensitive sub-sectors"。这比让所有 Hands 完全独立运行能获得更有针对性的信息，代价是串行化带来的延迟——策略决定什么时候值得级联。
L4Layer 4

GoalContext — 跨 Session 目标上下文

替代当前每次覆写的 last-synthesis.md。一个研判目标（如"NVDA Q3 研究"）可以跨多个 session 持续积累知识，synthesis 不是重置，而是叠加。

📋

GoalContext 新增

loom/brain_harness/goal_context.py · brain/goals/{goal_id}.json
  • 🆔 goal_id + status 生命周期：open（研究中，每次 synthesis 自动更新）→ investigating（有初步结论，Brain 监视 reversal 条件）→ concluded（已决策，归档但可检索）。每个 goal 独立存档，并发多个 goal 可以同时进行。
  • 🗂️ key_findings 累积：来自 Hand 结果和 Brain synthesis 的关键发现，不覆写只追加，用 superseded_by 字段标记哪些已被新发现替代。使 Brain 能回答"我们之前发现了什么，现在有什么新的"。
  • 📜 synthesis_history：每次 Brain synthesis 的结构化快照 [{ts, stance, confidence, key_drivers, reversal_condition}]，保留完整历史。支持 Structured Prediction Calibration（观察 stance 变化轨迹），支持用户理解"AI 的判断为什么变了"。
  • ⚠️ contradiction_log（跨 session）：同一冲突（宏观熊市信号 vs 企业微观强势）如果在多个 session 中反复出现，被标记为"结构性不确定性"，Brain synthesis 必须在 reversal_condition 中显式处理，不能简单取平均。
  • 📝 context_summary（动态摘要）：每次 synthesis 后 Brain 更新的目标状态摘要，取代当前 last-synthesis.md。作为下次 synthesis 的上下文输入，使 Brain 的 _assemble_prompt() 能获得连贯的历史上下文而不只是孤立的 last-synthesis。 
@dataclass
class Finding:
    finding_id:    str
    hand_id:       str          # 来源 Hand
    claim:         str
    confidence:    float
    ts:            str
    superseded_by: str | None    # 被哪条新发现取代，None = 仍有效

@dataclass
class GoalContext:
    goal_id:            str          # e.g. "market_research_NVDA_2026Q3"
    goal_type:          str          # market_research | position_review | macro_scan
    goal_description:   str
    status:             str          # open | investigating | concluded
    created_at:         str
    updated_at:         str
    strategy_id:        str          # 当前关联的 StrategyState

    key_findings:       list[Finding]          # 累积，不覆写
    synthesis_history:  list[SynthesisSnapshot] # 每次 synthesis 快照
    contradiction_log:  list[Contradiction]     # 跨 session 冲突记录
    context_summary:    str                    # Brain 每次更新的摘要
    episode_ids:        list[str]              # 关联的所有 episode
当前 vs 升级后：当前 last-synthesis.md 每次 write_last_synthesis() 都覆写，Brain 只看到"上一次"的结论。GoalContext 让 Brain 能看到"这个问题我们研究了 5 次，stance 从 hold 变到 buy 是因为 Q2 earnings beat 打破了之前的疑虑，但 macro 冲突仍然没有解决"——这才是分析师的工作方式。
L5Layer 5

DataFlywheel — 结构化原生数据与优化闭环

收集的不是衍生指标（reward = 0.73），而是 Brain 在执行过程中自然产生的决策记录——谁说了什么、Brain 如何判断、用户如何回应。这些数据是可审计的、可解释的，直接用于更新 L1 + L2。

🔄

DataFlywheel 新增

loom/brain_harness/flywheel.py · brain/flywheel/{flywheel_records}.jsonl
episode_id goal_id brain_self_eval hand_evaluations hand_self_reports orchestration_trace human_feedback (async) profile_signals (derived) strategy_signals (derived)
  • 🧠 brain_self_eval：Brain 对当次 synthesis 质量的自评：{synthesis_completeness: 0.82, key_drivers_specificity: 0.75, reversal_condition_quality: "specific|vague|missing", hand_coverage_gaps: ["earnings_hand missing EPS number"]}。Brain 在输出 synthesis 时同时输出这些结构化自评，不是事后计算。
  • 📋 hand_evaluations：OrchestrationLayer 按 EvalDimension 产生的每个 Hand 的评分：{hand_id: {dim_scores: {...}, overall: float, missing: [...], load_bearing: bool}}。load_bearing 标记该 Hand 是否实际被 Brain 引用为 key_driver——是"被引用率"的实时观察。
  • 👤 human_feedback（异步注入）：用户后续行为通过 episode_id 关联到该 episode，异步写入。信号类型：stance_accepted（正）、stance_modified（负 + 修改方向）、strategy_edit（最强信号）、anchor_delete（负）、reversal_triggered（预测质量验证）。
  • ⚡ FlywheelAnalyzer → 优化信号提取：定期（或积累 N 条后触发）分析 FlywheelRecord，提取：profile_signals（"用户在 NVDA research 中连续 3 次修改了 macro 权重 → belief_state.NVDA.uncertainty_source = macro"）和 strategy_signals（"earnings_hand 的 has_guidance_dim 与 stance_accepted 相关系数 0.73 → 提升该维度权重"）。 
@dataclass
class FlywheelRecord:

    goal_id:            str
    ts:                 str

    hand_evaluations:   dict[str, HandEval]  # {hand_id: dim_scores + load_bearing}
    hand_self_reports:  dict[str, dict]    # Hand 主动上报的质量信号
    orchestration_trace: list[PhaseTrace]  # 实际执行了哪些 phases + 触发条件
    conflict_log:       list[Conflict]    # 本 episode 检测到的冲突

    # 延迟注入 — 通过 episode_id 异步关联

    # FlywheelAnalyzer 计算 — 分析后填充
    profile_signals:  list[ProfileSignal]  # → IntentProfile 更新
    strategy_signals: list[StrategySignal] # → StrategyState 更新

↔在 Loom 中的位置

BrainStateEngine 与现有组件的交互关系

BrainStateEngine 不替换现有组件，而是在它们之上建立统一的状态主权层。各组件通过明确的读写接口与 BSE 交互。

📥 IntentWiki → L1 IntentProfile

IntentWiki 节点作为高置信度种子，被 IntentProfileUpdater 读取并合并到 active_intents。IntentWiki 继续接受用户的显式编辑，每次编辑触发 IntentProfile 同步更新。

IntentWiki.nodes → IntentProfile.active_intents (seed)

📚 BrainState → L2 StrategyState

BrainState 的 rules 和 frameworks 是 StrategyState 的可用工具库。StrategyState 从中按 IntentProfile 权重选取当前 goal 适用的规则和框架，而不是全量加载。

BrainState.query_frameworks(domain) → StrategyState.framework_ids

🔧 BrainHarness → L3 Orchestration

BrainHarness._assemble_prompt() 现在从 BrainStateEngine 获取 StrategyState + GoalContext，而不是直接拼接所有状态文件。OrchestrationLayer 的执行结果写回 BrainHarness 的 hand_artifacts。

BSE.get_prompt_context() → BrainHarness._assemble_prompt()

📡 IntentStream → L1 Update Loop

IntentProcessor 处理用户事件后，不只是 append 到 intent-stream.jsonl，而是同步触发 IntentProfileUpdater.on_intent_event()，实时更新 IntentProfile。

IntentProcessor.parse() → IntentProfileUpdater.on_intent_event()

🎨 canvas-client.js → episode_id 链路

Canvas 生成时，Brain 返回的 episode_id 被写入 card 的 data-anc-episode 属性。用户后续 refine/delete/build-on 该 card 时，canvas-client 携带 episode_id 调用 /intent/capture，使 human_feedback 能正确归因。

canvas generate → episode_id → card[data-anc-episode] → human_feedback

🔄 RewardedIntentHarness → DataFlywheel

现有 reward_ledger.jsonl 和 policy weight 机制迁移为 DataFlywheel 的一部分。FlywheelRecord 是 reward report 的超集（更多字段），FlywheelAnalyzer 取代 _update_policy_weights()，产生更细粒度的 strategy_signals。

reward_ledger → FlywheelRecord (superset)

分阶段实施——现有组件继续工作

BrainStateEngine 是增量演化的架构。每个阶段都是独立可运行的改进，不需要大规模重写。

P0

P0 — 数据骨架（1周）

建立数据基础，使所有后续阶段的数据积累从现在开始。GoalContext 替代 last-synthesis.md，episode_id 链路接通，FlywheelRecord 开始写入（字段逐步填充）。

goal_context.py（骨架） flywheel.py（write only） brain.py（episode_id 生成 + return） canvas-client.js（episode_id → card data attr）
P1

P1 — 评估层升级（2周）

StrategyState 第一版（规则驱动，非 ML），EvalDimension 手工定义，Evaluator 升级为 LLM-as-judge（异步）。飞轮信号开始有意义。

strategy_state.py（v1 规则派生） orchestration.py（EvalDimension 评分） harness/eval_log.py → flywheel.py brain_harness/base.py（接入 StrategyState）
P2

P2 — 意图画像（3周）

IntentProfile 从 IntentStream 历史中推断 belief_state + analytical_style。GoalContext 的 key_findings 开始跨 session 积累。FlywheelAnalyzer 提取 profile_signals。

intent_profile.py intent_processor.py（触发 profile update） goal_context.py（key_findings 累积） flywheel.py（FlywheelAnalyzer v1）
P3

P3 — 编排升级（4周）

HandConfig 策略派生，OrchestrationPlan MDP（phase 条件触发 + Lazy Evaluation），ConflictLog。Structured Prediction Calibration（200+ episodes 后）。

orchestration.py（MDP + HandConfig + LazyEval） hands/base.py（接收 HandConfig 参数） calibration.py（ECE + temperature scaling）
P4

P4 — 飞轮闭合（后续，500+ episodes）

FlywheelAnalyzer 完整版：strategy_signals 自动更新 EvalDimension 权重和 source_weights。Cross-Source Calibration（regime-dependent）。Similar past questions retrieval。

flywheel.py（FlywheelAnalyzer 完整版） strategy_state.py（飞轮驱动更新） retrieval.py（相似案例向量检索） cross_source_calibration.py
