Concern

The Session interface dropped the expiresAt field and added a touch() method on the store. This means expiration is now entirely store-managed. Confirm: (1) all store implementations (Redis, memory, DB) correctly implement TTL-based expiry, and (2) callers that previously read session.expiresAt have been updated.

Naming note

Renaming delete → remove avoids shadowing the JS keyword, but adds friction for developers familiar with the Map/Set .delete() convention. Consider destroy as a more idiomatic alternative.

Hunk 1 — route-level auth policy (line 1)

+ type AuthPolicy = 'authenticated' | 'optional' | 'admin' | 'public';
+
+ export function requireAuth(policy: AuthPolicy = 'authenticated') {
+   return async (req: Request, res: Response, next: NextFunction) => {
+     const token = extractToken(req);
+     if (!token && policy !== 'public' && policy !== 'optional') {
+       return res.status(401).json({ error: 'Authorization required' });
+     }
+     if (token) {
+       try {
+         req.user = await validateToken(token);
+       } catch (e) {
+         if (policy === 'authenticated' || policy === 'admin') throw e;
+       }
+     }
+     next();
+   };
+ }

Design note — composable middleware

This is the core value-add of the PR. The per-route AuthPolicy enum replaces what was previously hardcoded in a single authenticate() call. Note: the admin policy still needs a role-check (currently only validates token presence). Consider a follow-up PR that adds requireRole('admin') as a separate middleware step for cleaner separation of concerns.
